# Штукатур74 — сайт услуги механизированной штукатурки

Статический сайт (HTML + CSS + JS) с PHP-обработчиком формы. Без сборки и фреймворков:
папку можно залить на любой хостинг с PHP как есть.

## Структура

```
shtukatur74/
├── index.html        Главная: преимущества, сравнение с ручной, зона выезда, FAQ, контакты
├── services.html     Услуги: гипсовая/цементная, стены/потолки, под покраску/обои/плитку, субподряд
├── prices.html       Прайс + калькулятор стоимости
├── projects.html     Портфолио с блоками под фото до/после
├── contacts.html     Контакты, реквизиты, карта зоны выезда
├── privacy.html      Политика обработки ПД (152-ФЗ)
├── api/request.php   Приём заявки: почта + опционально Telegram (сейчас отключён)
├── css/styles.css
├── fonts/            Inter (variable, кириллица + латиница, 79 КБ) — самохостинг
├── img/              Фото объектов — только здесь, не на Google Drive
├── js/
│   ├── site.js       Контакты, навигация, мобильное меню, кнопки мессенджеров
│   ├── consent.js    Cookie-баннер и подключение Яндекс.Метрики
│   ├── form.js       Отправка заявки, проверка согласия на клиенте

├── .htaccess         Кодировка, заголовки, кэш, закрытые логи
├── robots.txt
└── sitemap.xml
```

## Текущее состояние: формы отключены

На сайте **нет ни одной формы сбора персональных данных** — до подачи уведомления
в Роскомнадзор. Заявки принимаются по телефону и в WhatsApp, они на месте.

Отключение сделано на двух уровнях, и снимать его нужно тоже на двух:

1. `js/site.js` → `SITE.formsEnabled: false`. Разметка формы лежит в `<template>`
   и в страницу не попадает: в DOM формы нет вообще, а не «скрыта стилями».
   Вместо неё выводится блок с телефоном и кнопкой WhatsApp.
2. `api/request.php` → `FORMS_ENABLED = false`. Обработчик отвечает 503 на любой
   запрос, поэтому прямой POST в обход сайта тоже ничего не сохранит.

**Включать обе константы только после того, как уведомление подано.** Заодно
проверить раздел 1.1 политики конфиденциальности — там написано, что форм нет,
этот текст нужно будет убрать.

## Заливка на хостинг REG.RU

1. В панели REG.RU открыть «Файловый менеджер» или подключиться по FTP/SFTP.
2. Содержимое архива распаковать в корень сайта — обычно
   `/var/www/u XXXXXXX/data/www/shtukatur74.ru/`. Внутри должны лежать
   `index.html`, `css/`, `js/` и т. д., **без** вложенной папки `shtukatur74`.
3. Проверить, что PHP включён (для `api/request.php`), версия 7.4 и выше.
4. В разделе «Домены» привязать `shtukatur74.ru`, выпустить бесплатный
   SSL-сертификат, затем раскомментировать редирект на HTTPS в `.htaccess`.
5. Файл `.htaccess` начинается с точки — в файловом менеджере включить показ
   скрытых файлов, иначе он не загрузится.

## Решения, которые важно не сломать при доработках

**Согласие на обработку ПД проверяется дважды.** `js/form.js` не даст отправить форму без
галочки, а `api/request.php` независимо отклоняет запрос с кодом 422, если поля `consent` нет.
Обход фронтенда ничего не даёт. Факт согласия пишется в `logs/consent.log` (дата, IP, версия
политики) — это доказательство на случай проверки.

**Яндекс.Метрика подключается только после клика «Принять».** В `js/consent.js` код счётчика
физически не выполняется, пока посетитель не согласился: никакого `<script src="mc.yandex.ru">`
в разметке нет. Кнопка «Только необходимые» запоминает отказ, и счётчик не грузится никогда.
Не переносите код Метрики в HTML — это сломает весь смысл баннера.

**Карта Яндекса грузится по клику** по той же причине: до нажатия кнопки страница не отправляет
запросов на сторонние сервисы.

**Мобильное меню не может разойтись с десктопным.** `js/site.js` клонирует ссылки из
`<ul class="nav-links">` в бургер-меню и в подвал. Добавили пункт в шапку — он сам появился
везде. При добавлении новой страницы правится только `<ul class="nav-links">`, но правится
**во всех HTML-файлах** — шапка статична в разметке ради индексации ссылок поисковиками.

**В шапке максимум 5–6 пунктов.** Больше — начинается перенос строк на ноутбучных ширинах.
Если разделов станет больше, выносите их в подвал или делайте выпадающее подменю, а не
добавляйте седьмым пунктом.

**Фото — только на своём хостинге, в `img/`.** Ссылки на Google Drive и Google Photos
использовать нельзя: на Android часть посетителей получает запрос авторизации вместо фото.

**Палитра и стиль — из скилла UI UX Pro Max.** Стиль «Minimalism & Swiss»,
палитра «Construction/Architecture» (индустриальный серый #64748B + сигнальный
оранжевый). Шрифт остался Inter: в датасете скилла пара для этого стиля —
Minimal Swiss = Inter / Inter, а рекомендованные генератором Outfit и Work Sans
кириллицу не поддерживают вообще, на русском сайте они бы отвалились в фолбэк.

**Оранжевый существует в двух оттенках, и менять это нельзя.** `--copper`
(#C2410C) — для текста и заливки кнопок: белый на нём даёт 5.18:1, проходит
WCAG AA. `--copper-light` (#EA580C) — только для тёмных секций (5.02:1 на
`--ink`) и hover. Яркий оранжевый на белом даёт 3.56:1 и для текста не годится;
если поменять их местами, половина сайта перестанет проходить по контрасту.

**Шрифт самохостинг.** `fonts/InterVariable-cyrillic-latin.woff2` — Inter 4.1, урезанный до
кириллицы и латиницы (79 КБ вместо 352 КБ), все начертания 100–900 в одном файле.
Запросов к Google Fonts на сайте нет.

## Юридический чек-лист

- [ ] Дописать ФИО ИП и адрес регистрации в `privacy.html` (разделы 1 и 11) и в подвале.
- [ ] Указать адрес хостинг-провайдера в разделе 6 политики.
- [ ] Назначить ответственного за взаимодействие с Роскомнадзором по инцидентам (раздел 11).

      на сайте отключены — см. раздел «Текущее состояние» выше. Это отдельная обязательная
      процедура, политика на сайте её не заменяет.
- [ ] В уведомлении указать все три категории субъектов: клиенты, представители контрагентов,
      мастера-подрядчики. Форма на `contacts.html` принимает обращения по субподряду, значит
      эта категория появится в тот же момент, когда включат форму.
- [ ] После подачи уведомления: `SITE.formsEnabled = true`, `FORMS_ENABLED = true`,
      убрать раздел 1.1 из политики.
- [ ] Проверить, что `logs/` недоступна из браузера (в `.htaccess` правило есть, но на nginx
      его нужно продублировать в конфиге сервера).
- [ ] Любое новое поле в форме — сначала в политику и в уведомление, потом в разметку.

## Локальный запуск

```bash
php -S localhost:8000 -t shtukatur74
```

Пока формы отключены, `api/request.php` на любой запрос отвечает 503 — это ожидаемо.
Чтобы проверить форму локально, временно поставьте `SITE.formsEnabled = true` и
`FORMS_ENABLED = true`: без настроенного MTA письмо не уйдёт и обработчик вернёт 502,
но логика согласия проверяется раньше — 422 без галочки приходит до отправки письма.
