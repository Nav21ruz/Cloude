# База знаний для ИИ-агента маркетолога — Штукатур74

Этот файл вместе с `knowledge-base.json` — то, что нужно загрузить в
ИИ-агента (кастомный GPT, Claude Project, любой LLM-инструмент с
файлом-контекстом), которому вы поручите рекламу, посты, объявления
или тексты для shtukatur74.ru. Цель — чтобы агент отвечал фактами
с сайта, а не выдумывал их.

## Что внутри

- **knowledge-base.json** — структурированные факты: реквизиты, цены,
  гарантия, процесс работы, категории качества, контакты, статьи,
  аналитика, рекламные креативы, фирменный стиль. Всё взято с живого
  сайта или из внутренних документов проекта на момент генерации
  (09–10.08.2026).
- **guardrails.md** — жёсткие правила, что агенту НЕЛЬЗЯ писать. Это не
  рекомендации, это ограничения. Дайте агенту инструкцию прочитать этот
  файл первым и следовать ему без исключений.

## Как подключить

**Кастомный GPT / Claude Project / Gemini Gem:** загрузите оба файла как
knowledge files, в системный промпт агента добавьте одну строку:
«Перед тем как писать любой текст про Штукатур74, сверься с
knowledge-base.json и строго соблюдай guardrails.md».

**Просто вставить в чат:** скопируйте содержимое обоих файлов в начало
разговора с любой ИИ-моделью перед тем, как просить рекламные тексты.

## Как поддерживать актуальность

Это снимок сайта на конкретную дату (`generated` в JSON). Цены,
гарантия, контакты и статус формы могут поменяться. Если вы попросите
следующую сессию Claude Code на этом проекте что-то изменить на сайте
(цену, гарантию, контакты) — попросите её же обновить и
`knowledge-base.json`, иначе агент-маркетолог начнёт рекламировать
устаревшие условия. Самое хрупкое место — `pricing` и `contacts`
(особенно `lead_form_status` — включена ли форма).

## Известные пробелы (не выдумывать)

В `knowledge-base.json` есть раздел `known_gaps` — это честный список
того, что владелец не подтвердил: часы работы, налоговый режим, статус
ККТ, подана ли уже форма-уведомление в РКН, реальная маржинальность,
не хватает города/площади/срока у части объектов портфолио. Агент
должен либо не упоминать эти вещи, либо явно спрашивать пользователя,
прежде чем что-то про них утверждать.
